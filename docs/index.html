How protected do you want to be?

Four independent layers. Each is opt-in, each answers a different question about who you're defending against. Start at the top and add what you need.

01

Vaultset · run

Keys stop living in .env files, repos, screenshots and shell history. The value reaches one child process and nothing else.

02

Protected secretsenroll · protect

Encrypted at rest under a key only your unlock factor recovers. Someone else at a shared or public machine gets ciphertext.

03

Proxy modeproxy start

The tool never receives the key. It calls 127.0.0.1, the proxy injects the credential upstream and strips whatever the client sent.

04

Service modeinstall_proxy_service.ps1

The vault moves to an account you can't read from your own session. Create, list and delete still work; reading simply isn't implemented.

02

Four ways to unlock

One master key encrypts your secrets; every enrolled factor wraps its own copy. Enroll two, and losing one is an inconvenience rather than a lost vault.

⌨️

Passphrase

PBKDF2-SHA256 at 600,000 iterations. Works anywhere, nothing to carry, nothing to lose.

Always available
👤

Windows Hello

PIN, fingerprint or face. The wrapping key is TPM-bound, so a copied vault is inert on any other machine.

Needs a TPM
🔑

FIDO2 security key

A YubiKey via the CTAP2 hmac-secret extension. Physical touch on every unlock — the secret never leaves the token.

Strongest
💾

Keyfile

A thumbdrive. Plug it in and secrets open with no typing at all; unplug it and the vault is shut. Matched by id, so drive letters can change.

Zero friction

How it stacks up

This isn't trying to be Doppler. It occupies a narrow niche: a solo developer on Windows who wants tools and AI agents to use API keys without ever holding them — offline, no account, nothing installed.

Three rows here are genuinely uncommon. The proxy — nothing else on this list keeps the key out of the client's hands. Hardware-unlocked local storage — 1Password offers Windows Hello, but as biometric unlock of a cloud account; a YubiKey touch decrypting a purely local vault with no account behind it is close to unique. And service mode, which has no equivalent at all.

Use 1Password or Doppler if…

More than one person needs the key. The moment sharing, rotation, or an audit trail matters, every cloud option beats this one.

Use gopass or envy if…

You're not on Windows. shush is Windows-only by design and will stay that way.

Use anything older if…

You need audited cryptography. This implements AES-CBC+HMAC, PBKDF2 and a hand-written CTAP2 stack — careful and test-covered, but new and unaudited.

04

Sixty seconds

git clone https://github.com/latranchee/shush.git
# store a key — prompts securely, never echoes, never hits disk shush set openai_api_key # run any tool with the key in its environment and nowhere else shush run codex --env OPENAI_API_KEY=openai_api_key # on a shared machine: encrypt it, unlock with a thumbdrive shush enroll --keyfile shush protect openai_api_key # or let the agent call the API without ever holding the key shush proxy start

Requires Windows 10/11 and either Windows PowerShell 5.1 (built in) or PowerShell 7+. There is nothing to build and nothing to install system-wide — it's PowerShell and the Win32 credential APIs.

05

What it doesn't do

▲ Read this before trusting it with anything

  • It can't protect an unlocked session. Once you unlock a key to use it, the plaintext is in memory and in the child process. Nothing here changes that.
  • A keyfile is a bearer token. Anyone who copies it holds the vault, and copying leaves no trace. Only the FIDO2 factor resists that, because its secret never leaves the token.
  • TOTP is not offered on purpose. An authenticator app verifies, it doesn't encrypt — and verifying needs the seed stored on the same machine as the keys it guards.
  • Hello and FIDO2 are not yet hardware-verified. The passphrase and keyfile factors are covered by automated tests on both PowerShell hosts. The other two are implemented and test-covered in software, but haven't been run against a real TPM or token. Don't make either your only factor until you've run the hardware suite.
  • It is not a defence against a hostile administrator on the machine, and it never claimed to be.
